# Database Setup Guide – Supabase Managed PostgreSQL & Alembic

This guide provides step-by-step instructions for configuring **Supabase Managed PostgreSQL** and running **Alembic database migrations** for **The Cost of Waiting – Smart Queuing for Public Hospitals**.

---

## 1. Cloud Architecture Overview

```
┌─────────────────────────────────┐
│     React Frontend (Vercel)     │
└────────────────┬────────────────┘
                 │ HTTPS REST API requests
┌────────────────▼────────────────┐
│     FastAPI Backend (Render)    │
└────────────────┬────────────────┘
                 │ Secure TLS/SSL Connection (Psycopg 3 via Session Pooler)
┌────────────────▼────────────────┐
│  Supabase PostgreSQL Database   │
└─────────────────────────────────┘
```

> **Security Rule:** The React frontend **NEVER** connects directly to PostgreSQL or Supabase. All database access and validation is mediated through the FastAPI backend.

## 2. Supabase Project Creation Instructions

1. Go to [supabase.com](https://supabase.com) and sign in (or create a free account).
2. Click **New Project**.
3. Choose your organization and specify:
   - **Project Name:** `smart-queue-hospital` (or similar)
   - **Database Password:** Enter a strong password and **save it in your password manager**.
   - **Region:** Select a region close to your Render deployment (e.g., `East US (North Virginia)` or `West US (Oregon)`).
   - **Pricing Plan:** Free tier is sufficient.
4. Click **Create new project** and allow 1–2 minutes for the database instance to provision.

---

## 3. Obtaining the Supabase Session Pooler Connection String

For cloud-hosted backends (Render) and local development, Supabase's **Session Pooler** is strongly recommended to safely manage connection limits:

1. In your Supabase Project Dashboard, click the **Settings (cog icon)** at the bottom left.
2. Navigate to **Database**.
3. Scroll down to the **Connection string** section.
4. Select the **URI** tab.
5. Choose **Session Mode** (uses port `6543`):
   - Connection string template:
     ```text
     postgresql://postgres.[PROJECT-REF]:[YOUR-PASSWORD]@aws-0-[REGION].pooler.supabase.com:6543/postgres
     ```
6. Alternatively, for Direct connection, choose **Direct connection** (uses port `5432`):
   - Connection string template:
     ```text
     postgresql://postgres:[YOUR-PASSWORD]@db.[PROJECT-REF].supabase.co:5432/postgres
     ```

## 4. Configuring `DATABASE_URL` with SSL Mode

SQLAlchemy with the **Psycopg 3** driver requires the URL scheme `postgresql+psycopg://`. Our backend automatically converts standard `postgresql://` strings, but for best practice, format it as follows:

In `backend/.env`:
```env
# Session Pooler (Port 6543) - Recommended
DATABASE_URL="postgresql+psycopg://postgres.[project-ref]:[your-password]@aws-0-[region].pooler.supabase.com:6543/postgres?sslmode=require"
```

### Enabling SSL
Append `?sslmode=require` to the end of the connection URI. This guarantees that all communication between Render/local machine and Supabase is encrypted with TLS.

## 6. Alembic Database Migrations

Alembic is configured to read the connection URL dynamically from `backend/.env` using `app.config.settings`.

### Common Alembic Commands (run inside `backend/`):

1. **Check current database revision:**
   ```powershell
   alembic current
   ```

2. **Generate a new migration (autogenerated from SQLAlchemy models in Checkpoint 2+):**
   ```powershell
   alembic revision --autogenerate -m "create_initial_queue_schema"
   ```

3. **Apply all pending migrations to Supabase:**
   ```powershell
   alembic upgrade head
   ```

4. **Rollback the latest migration:**
   ```powershell
   alembic downgrade -1
   ```

5. **View migration history:**
   ```powershell
   alembic history --verbose
   ```

> **Note for Checkpoint 1:** No application tables (patients, tickets) are generated yet. The Alembic pipeline is established and ready to deploy tables in Checkpoint 2.
